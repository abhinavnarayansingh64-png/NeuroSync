# Visual verification notes

The current public landing route was reviewed in the managed preview. It presents the black-first NeuroSync visual system with cream typography and controls, the right-side animated PC-to-GPU strand field, stacked endpoint labels, and readable public actions. The landing interactions include reduced-motion safeguards and keyboard-visible focus states.

The authenticated Receiver workspace was reviewed through its protected entry path. Browser Receiver pages are intentionally desktop-first: browser users retain Job History and Earnings & Analytics, while job acceptance and native hardware operations are directed to the Electron client. A pending assignment is pinned above the account-level status content, and runtime RAM/VRAM fields are displayed only when reported by the connected desktop receiver. Missing telemetry is shown as unavailable rather than inferred.

The Electron desktop client has a separate Hardware page and startup role selection. Its native diagnostic path was exercised in the Linux sandbox and returned actual host CPU, RAM, platform, and architecture values while honestly reporting unavailable NVIDIA, CUDA, and PyTorch components on that host. A Windows RTX device is required to validate real GPU values, Windows OAuth, and the complete multi-device lifecycle.

Visual review is not a substitute for authenticated production verification. Before submission, sign in on the published domain, run the desktop client on the intended Windows receiver, and capture the sender/receiver offer, acceptance, transfer, execution, and earnings flow.
